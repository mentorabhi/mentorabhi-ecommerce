# S1-M08 — Graph, lakehouse and reporting

Status: Automated local acceptance passed for final source-to-Iceberg reconciliation, unchanged replay, graph projection/API, analytics report routes and Selenium journeys. Owner browser/Trino/database checks remain pending. See the dated [verification record](verification.md) for measured results and limits.

Architecture proposal: [S1-M08 diagram](../../../architecture/stage-1/S1-M08.excalidraw). Implementation design: [design](design.md), [editable flow](flow.mmd), [review](design-review.md), [metrics/dashboard](dashboard-and-metrics.md), and [manual acceptance](manual-acceptance.md). The standard commerce metrics increment has a separate reviewed [design](standard-commerce-metrics-design.md), [review](standard-commerce-metrics-review.md), and editable [flow](standard-commerce-metrics-flow.mmd).

Initial technology decisions for implementation: Neo4j Community for bounded product/order relationships; Spark and Iceberg for replayable event facts; Trino for local SQL reporting. Analytics workloads are opt-in and selective on the 16 GB Mac. Source data is the public Orders lifecycle event envelope from Kafka, never another service's private database. Only privacy-reviewed allowlisted facts are projected.

Implementation includes a bounded local Neo4j graph projection/API, an idempotent Kafka-to-Iceberg Spark batch job, per-currency curated report tables, a Trino JDBC catalog, a read-only analytics API, and an operator dashboard in the storefront admin. Standard reports include period controls, GMV, order value/count, AOV, discounts/rate, item units, refunds/rate, net cash activity, cancellation/return activity, daily trend, top products, and refund reasons. Superset is an optional local dashboard studio. Funnel, customer retention, coupon attribution, and inventory KPIs await their source events or owner APIs. Development lives in `services/analytics-api/`, `services/relationship-graph/`, `data/pipelines/lakehouse/`, `contracts/order_events.py`, and `apps/storefront/src/CustomerStore.tsx`. Keep Spark and graph jobs opt-in; on the 16 GB baseline stop Trino before a Spark batch and restart it after. Actual outcomes and still-open checks are in [verification](verification.md); manual end-user steps are kept separately in [manual acceptance](manual-acceptance.md).
