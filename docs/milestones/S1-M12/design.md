# Local request telemetry

2026-10-25 · R28 / AE28 · Design reviewed before source implementation. Coding first, data second, testing last; all runtime claims below are targets until measured.

Instrument the eleven independently built Java commerce/history services with the OpenTelemetry Java agent. Propagate W3C trace context through HTTP/JDBC and export OTLP/HTTP to an internal Collector. Preserve service ownership: telemetry never queries private databases and cannot change deterministic money/stock/ownership decisions. Python analytics/graph and browser instrumentation are outside the initial request-tracing scope and must be labelled accordingly in dashboards.

The optional observability profile adds Collector, Tempo and Loki alongside existing Prometheus/Grafana. Prometheus scrapes Collector's request metrics, Tempo stores traces on a local named volume, Loki stores safe request logs on a local named volume. Grafana provides human visualization at localhost:3001 using admin/admin. Collector/Tempo/Loki have no host ports. No cloud telemetry endpoint, hosted fallback or vendor reporting is enabled. Agent setup download is a build prerequisite, distinct from runtime export.

## Privacy and cardinality

Application request logs use a dedicated `supersports.http` logger and fixed plain message `http_request`. A servlet filter records method, status, elapsed milliseconds and a bounded Spring route template after dispatch. Unknown/security-rejected routes use `UNMATCHED`, never the submitted URI. No body, query, username, address, order ID, exception text, header or authorization token is logged by this filter. Preserve agent-generated trace/span context. Collector drops every other application log from this exported stream and retains only the explicit safe log attributes. Local console logs remain operational diagnostics outside Loki's deliberately narrow request-log scope.

Collector trace sanitization retains service name, span kind, trace/span IDs and a short allowlist: route template, method, response status, database system/operation and server port. Replace span names with bounded operation descriptions; remove events/links/exception strings and resource attributes beyond service name/version/environment. Never export SQL text/bind values, URL/path/query, customer IDs or baggage. Agent header capture is off, database statement sanitization remains on. Metrics retain route/method/status attributes only, without raw paths. A sentinel-containing request/failed request must prove exclusion during final integration; configuration inspection alone does not establish privacy acceptance.

Source-review refinement before enabling runtime export: clear incoming W3C tracestate as well as attribute/header data. It is a propagation field outside the attribute map and could contain caller-supplied text. The live privacy case includes the sentinel in tracestate, query and a private header, and requires its absence from stored traces/logs while trace IDs still link.

## Lifecycle, versions and resources

Agent is present in app images but SDK-disabled by default. A dedicated `telemetry-up` operation starts the observability profile and recreates running Java applications with SDK enabled, preserving each current image ID and active History target. Persist that project-local selection under ignored local state so ordinary lifecycle commands retain it. `telemetry-down` disables SDK/recreates the same running apps before stopping backends. Commerce continues without telemetry; exporter failure is not readiness failure. Avoid automatically starting graph/analytics/Superset alongside this profile on the 16 GB host.

Official release API metadata checked 2026-10-25 selects Collector contrib 0.163.2, Tempo 3.1.1, Loki 3.7.9 and Java agent 2.33.0. Agent release asset SHA-256 is `5f9d1f10056ed2b246fbb19543519b8066cda23d6aff19022dbdb84402d6c3ab`. Collector/agent are Apache-2.0; Tempo/Loki are AGPL-3.0. Existing Prometheus/Grafana pins remain. Image digest/ARM64 metadata and Java 27 instrumentation compatibility must be resolved and recorded before runtime acceptance; release metadata alone is not a successful deployment.

Proposed container caps: Collector 192 MiB, Tempo 384 MiB, Loki 256 MiB, plus existing Prometheus 384/Grafana 512/health exporter 128 MiB. Sample actual per-container/total memory during final integration. Retain traces 24 hours and logs 24 hours, with bounded ingest/query concurrency and chunk/block tuning. Retention is time-based, not a guarantee of a fixed disk quota; report volume sizes and finite measured behavior. Prometheus retains its existing 7-day/512 MB bound. Export queues are bounded in memory, so collector/backend outages may lose telemetry; commerce is authoritative.

## Reviewed decisions and verification

Host review covered runtime locality, independent builds, safe templated routes, untrusted unmatched URLs, exception/SQL data, shutdown order, explicit profiles, image preservation and inactive optional services. Preserve the small per-service request filter as intentional duplication to keep service projects independent. Review source changes again before final shipping; this design review is not a code-review receipt.

Author unit tests for request filter emitted fields and exception path, lifecycle selection/image preservation and pipeline structure. Run only after data phase: all affected Java and Devops suites; real request metrics (traffic/error/latency histogram), HTTP/client/JDBC trace linkage, Loki request log with matching trace ID; sentinel privacy; collector outage and disable/restart; Grafana login/dashboard/Explore Selenium; restart retention and measured resources. Record versions, exact commands, request dataset and limitations. Maintain the separate manual checklist.

Runtime refinement: Collector validation accepts list literals for span events/links but the typed pdata setters reject [] at execution. Use set(events, nil) and set(links, nil), which the pinned contrib v0.163.0 SetPSliceValue implementation explicitly converts to empty typed slices. Preserve error_mode=propagate. Add a direct internal OTLP sentinel fixture containing nonempty events/links/tracestate and require sanitized stored output, alongside the real Java request test. Source: https://github.com/open-telemetry/opentelemetry-collector-contrib/blob/v0.163.0/pkg/ottl/contexts/internal/ctxutil/slice.go .

Startup refinement from actual re-enable failure: Compose can report Grafana started without an HTTP healthcheck while /api/user still refuses connections. Add a container-local wget /api/health check (verified executable present), bounded by the existing 180-second lifecycle wait, before account provisioning. This is readiness only: it does not reset credentials, relax authentication or change app/History image selection. Re-run from a stopped Grafana container to prove the ordering.

Recovery-probe refinement: a restarted Tempo backend can make Grafana return a non-JSON HTTP error. The shared JSON probe must retain that HTTP status with an empty redacted body, close the response, and allow the existing bounded wait predicate to observe recovery. Its HTTPError branch previously decoded outside the sibling exception guard. Add plain-text/HTML/invalid-encoding error-body unit cases before fixing that branch. Preserve the five-second transport timeout and all runtime assertions.

Asynchronous trace/recovery test refinement: trace views may expose partial service batches before the required parent edge arrives. A live diagnostic observed Orders-only spans from 3.808 seconds until the Fulfillment/client edge was visible at 10.813 seconds. Wait for the actual parent-edge criterion within the existing deadline, retaining all assertions. During Collector restart, exporter failure/loss is explicitly allowed by bounded-queue design: issue safe reads throughout recovery and require a post-recovery trace to become queryable, rather than requiring one request sent immediately after process start to survive. Keep the same 60-second recovery bound and check every read succeeds.
